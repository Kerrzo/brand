<ArticleSection dark id="the-question">
  <ArticleTwoCol>
    <SectionLabel slot="label">01 / The question</SectionLabel>
    <h2 class="h-2">How close is a fast local coding model to the frontier?</h2>
    <p class="body-copy">Local AI has an obvious appeal: privacy, control, predictable cost and the ability to experiment without sending every prompt to a hosted service.</p>
    <p class="body-copy"><strong>The less obvious question is whether it can do work I would trust.</strong></p>
    <p class="body-copy">I wanted something harder to judge than a small function or a familiar coding exercise, so I asked three models to implement the same in-memory TypeScript task scheduler.</p>
    <p class="body-copy">The scheduler needed bounded concurrency, priority ordering, FIFO behaviour, retries, timeouts, cancellation, pause and resume—and it had to settle every accepted task exactly once.</p>
    <p class="body-copy"><strong>One requirement made the task particularly revealing: a timed-out promise may keep running, so it must continue occupying a real concurrency slot.</strong></p>
  </ArticleTwoCol>
</ArticleSection>

<ArticleSection id="the-comparison">
  <ArticleTwoCol>
    <SectionLabel slot="label">02 / The comparison</SectionLabel>
    <h2 class="h-2">The speed surprised me. The code quality surprised me more.</h2>
    <p class="body-copy">The local run used an Unsloth Qwen3.6 35B-A3B MTP GGUF at Q4 in LM Studio, running on an RTX 5090 with native multi-token prediction enabled.</p>
    <p class="body-copy">Across the captured screenshots it decoded at <strong>roughly 266–270 tokens per second</strong>, with a reported time to first token between 0.42 and 0.59 seconds.</p>
    <p class="body-copy">Its complete 12,169-token response implies <strong>about 45 seconds of decoding.</strong> That is an estimate, not a measured end-to-end duration.</p>

<ArticleSection dark id="what-the-speed-hid">
  <ArticleTwoCol>
    <SectionLabel slot="label">03 / What the speed hid</SectionLabel>
    <h2 class="h-2">Fast output is not the same as correct software.</h2>
    <p class="body-copy">The Qwen response looked plausible at a glance. It used a heap for priority ordering, tracked task state and attempted to guard against double settlement.</p>
    <p class="body-copy"><strong>But the captured implementation had defects in the exact places the task was designed to test.</strong></p>
    <p class="body-copy">Its physical concurrency counter was decremented without being incremented. A timeout released capacity even though the underlying work could still be running. Retry bookkeeping removed the task from the active-ID map too early. The captured status type also did not include values later assigned by the implementation.</p>
    <p class="body-copy"><strong>The code was quick to produce and expensive to trust.</strong></p>
    <p class="body-copy"><strong>Codex and Claude handled the core concurrency model much more carefully.</strong> Both separated the scheduler's decision about an attempt from the physical lifetime of the underlying promise—a small architectural distinction with a large effect on correctness.</p>
  </ArticleTwoCol>
</ArticleSection>

<ArticleSection id="the-conclusion">
  <ArticleTwoCol>
    <SectionLabel slot="label">06 / The conclusion</SectionLabel>
    <h2 class="h-2">Local AI is closer. It isn't interchangeable.</h2>
    <p class="body-copy"><strong>This was one prompt, one local setup and one informal review.</strong> It does not establish a general ranking of the models.</p>
    <p class="body-copy">But it changed my mental model.</p>
    <p class="body-copy"><strong>The local model was not a toy.</strong> Its speed was remarkable, and parts of its approach were sensible. For exploration, private work and tasks where I can cheaply verify the answer, that is already useful.</p>
    <p class="body-copy">For a concurrency primitive where a subtle mistake could corrupt everything built on top of it, <strong>the frontier implementations were in a different class.</strong></p>
    <p class="body-copy"><strong>The question is no longer whether local AI can write serious-looking code. It can. The question is where the cost of verifying it becomes greater than the value of running it locally.</strong></p>
  </ArticleTwoCol>
